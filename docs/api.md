# Pinakes API v1

This reference describes the utoipa API exposed at **`GET /v1/openapi.json`**.
The [OpenAPI snapshot](openapi.json) is regenerated by `scripts/openapi`.
Pinakes returns resource metadata and ranking. Clients hydrate social state from
Nexus in a separate call. All paths below are relative to the Pinakes origin.

## Routes

| Method and path | Input | Response |
| --- | --- | --- |
| `GET /v1/search` | Query parameters below | `{items, cursor, reach_truncated, facets?}` |
| `GET /v1/resources/{id}` | `fields=card\|facets\|document` | One resource; default `document`; 404 if absent |
| `POST /v1/resources/lookup` | Exactly one of `{"ids":[...]}` or `{"uris":[...]}` | Array in request order, including duplicates, skipping unknowns; 1–500 entries |
| `POST /v1/resolve` | `{"uri":"https://example.org/"}` | Resource immediately or after up to 3 seconds; 202 with `status=pending` while queued |
| `GET /v1/resources/{id}/occurrences` | Optional RFC 3339 `from`, `to`, `limit` (1–500), signed `cursor` | `{items:[...],cursor}` in start/key order; default horizon/100 rows; unknown resource 404 |
| `GET /v1/groups/{id}` | 32-character group ID | Group card, members and distinct taggers; 404 if unknown |
| `GET /v1/info` | None | Public version, manifests, resolver status, counts, ingestion cursor/epoch/length/lag/time and licence |
| `GET /v1/changes` | `cursor`, `class`, `type`, `source`, `limit` | Change page with ascending sequence cursor |
| `POST /v1/changes/lookup` | `{resource_ids:[...], since, cursor?, limit?}` | Changes to 1–500 requested IDs since a timestamp |
| `GET /v1/resources/{id}/changes` | Same filters as changes | Resource history, including after expiry |
| `GET /v1/dumps/osm_place.ndjson` | None | Streaming ODbL notice followed by every `osm_place` row; 2 requests/minute per socket IP by default |
| `GET /v1/openapi.json` | None | Generated OpenAPI 3.1 |

`lookup` also accepts the Nexus-compatible alias `resource_ids` for `ids`.
Unknown URIs do not cause a fetch. Known overdue resources are moved to the front
of the refresh queue without bypassing TTL, backoff, leases or final state. URIs are normalized and IDs computed
by `pubky-resource-id`. Each URI is at most 2048 bytes; IDs are 32 lowercase hex
characters. A missing upstream object is a known resource with `status=missing`,
not an HTTP 404 from the Pinakes resource route.

## Search

| Parameter | Meaning |
| --- | --- |
| `q` | Full-text name/description search with trigram/partial-name fallback; max 256 bytes |
| `type` | Any pinned schema.org type, including ancestors (`Event` includes `MusicEvent`) |
| `category`, `scheme`, `host` | Exact resource facet filters |
| `tags` | Comma-separated labels; at most 5; each 1–128 bytes |
| `match` | `any` (default) or `all` (at most 3 tags) |
| `author` | Resources referenced by this 52-character z-base-32 public author ID |
| `reach` | `following` or `friends`; requires `viewer`; restricts reference/tag filters |
| `viewer` | Nexus user ID used only for the reach set |
| `sort` | `activity` (default), `recent`, `distance` (requires `near`) or `start` |
| `limit` | 1–500, default 50 |
| `cursor` | Authenticated next-page token returned by this daemon; restart pagination after a daemon restart or an invalid-cursor 400 |
| `facet` | `tags`: counts distinct result units per label over the entire filtered set |
| `bbox` | `minLon,minLat,maxLon,maxLat`, degrees; west > east crosses the antimeridian |
| `near`, `radius` | `lat,lon` plus a positive metre radius, max 200,000 by default; mutually exclusive with `bbox` |
| `from`, `to` | Inclusive start-time bounds, RFC 3339 or Unix milliseconds; `from` must not follow `to` |
| `cluster` | Finite map zoom with `bbox`, floored and clamped into the resolution table; returns viewport clusters/points; incompatible with cursor |
| `fields` | `card` (default), `facets`, or `document` |
| `collapse` | `group`: filter members, deduplicate groups, then rank/page or cluster |

`venue` accepts a 32-character resource ID for events at that place.
`collapse=group` returns one best-member row per group after member filters.
`reach=wot_2` and other collapse values return 400. Unknown parameters, invalid
coordinates/dates, out-of-range radius, non-finite zoom and incompatible options also return 400.
The `start` sort excludes resources without a start. Distance and start ranks are
negative metres and negative Unix seconds respectively, so nearest/earliest comes
first while preserving the descending keyset contract.

Spatial search includes `point` even with `fields=card`. OSM cards always include
`osm_id` (for example `node/123`) and `attribution: "© OpenStreetMap contributors
(ODbL)"`. Type ancestry includes both parents of `LocalBusiness`, so `type=Place`
includes cafés and other businesses. Spatial, time, text, type, tag and reach filters
can be combined; tag facets count the complete filtered set before pagination.

`cluster=<zoom>` returns `{clusters, points, truncated, total, reach_truncated, resolution,
facets?}`. Each cluster is `{cell,count,lat,lon,top:[resource_ids],attribution?}`.
`top` contains at most three IDs ordered by the selected rank. The centroid comes
from member points (circular longitude mean handles the dateline). H3 resolution
is `clamp(floor(zoom)-4,0,11)` by default, configurable via a table. Large viewports
may coarsen further to fit the cell budget; `resolution` reports the effective value.
Singleton cells are points; if total filtered resources <= limit, all are points.
The limit caps returned clusters plus singleton points, and `truncated` marks any
omitted units. When not truncated, sum(cluster counts)+points.length equals total.
There is no cursor in cluster mode; refine the viewport/zoom to retrieve omitted units.

Search responses carry `Cache-Control: public, max-age=30` and an `ETag` hashing
parameters, ingestion cursors/epochs, a transactionally maintained write revision,
the reach-author-set hash and its truncation flag. `If-None-Match` returns 304 when
unchanged. The reference scope belongs in the URL, so reach/viewer searches have
separate cache keys.

One SQL statement performs type/facet and text filtering, reference/tag/reach
filtering, ranking, tag aggregation and pagination. Facets are computed before the
page limit and use the same author/reach scope. Resources without public references
are excluded. Following/friends lists come from Nexus in pages of 200, cached per
viewer and reach kind for five minutes, with at most 1,000 authors. A further page
probes for truncation; `reach_truncated=true` warns that the reach set was capped.
The cache lock is released during fetching, so one slow viewer does not block another.
All pages share a total five-second deadline (`search.reach_timeout_secs`); incomplete
sets are not cached. An unknown Nexus user has an empty reach set; errors or deadline
expiry return 502, not an empty successful search.

Keyset cursors authenticate the complete payload with HMAC-BLAKE3. The random key is
created at daemon startup and never persisted or exposed. Tampered/unsigned cursors
and cursors from a previous daemon return 400; restart pagination without a cursor.

Activity ranking uses distinct taggers and reference counts:

```text
(log(1 + taggers) + 0.5*log(1 + replies) + 0.3*log(1 + embeds + collections))
  * 2^(-age_of_newest_reference_in_days / 30)
```

Scores are recomputed on reference changes and continue to decay at search time.
`recent` ranks by the newest reference timestamp. Pagination orders descending on
`(rank, resource_id)`. Scores are internal to ordering, pagination and cluster `top`
selection; public resource responses omit them. The cursor pins the
decay timestamp and binds to the filters. Keep all filters, field selection and
sort unchanged; `limit` may change. Concurrent reference/resolver updates are
visible (this is not a frozen database snapshot). Corrupt or mismatched cursors
return 400. A null cursor ends the result set.

## Resource fields and status

Cards include `resource_id`, `uri`, `type`, `name`, `description`, `image`, `site`,
`status`. Missing card values are null. `facets` adds `type_path`, optional
`category` and `point:{lat,lon}`. Event `start`/`end` also appear on cards. `document` adds the bounded
`ResourceMeta` with source, fetched time in Unix milliseconds, TTL seconds,
attributes and aliases. `geo` omits `ttl_secs` because it is final. The document is at most 8 KB; its flat string attributes
are resolver-allowlisted and capped at 32. An unresolved resource has no document.

Statuses are `ok`, `pending`, `missing`, `unreachable`, and `error`. Missing must
be confirmed by two fresh successful fetches; one missing response keeps the last
accepted status/document, and a repeated cached observation does not count twice. `unreachable`
means the upstream denied access; `error` can have a scheduled retry or be in dead
letter. Failed refreshes preserve the last accepted document, whose own status/time
reflects that older fetch. Alias URLs do not change resource identity. Image URLs
point to the origin; Pinakes does not serve or proxy image bytes.

`location_source` is `uri`, `osm`, `page` or `geocoded`. The geo resolver accepts the
RFC 5870 grammar, including altitude, WGS84 CRS, uncertainty and extension parameters;
altitude/uncertainty are ignored. Unsupported CRS and malformed coordinates resolve
to an error. Geo names preserve the latitude/longitude spelling and
`attributes.precision` estimates formatting resolution from the less precise axis:
five+ decimals ≈1 m, four ≈10 m, three ≈100 m, two ≈1 km, zero/one ≈10 km (clamped).
This is a formatting hint, not a measurement-uncertainty claim. No reverse geocoding.

OSM documents include `osm_id`, `location_source:osm`, `bbox` in API bbox order,
`address` (street, house_number, postcode, city, country_code when present), category,
allowlisted attributes and attribution. OSM metadata is composed from `osm_place`
at read time. The resource table contains only OSM IDs and a minimal envelope.
`/v1/info` declares ODbL and the dump URL; the dump's first NDJSON line declares its
licence, followed by a repeatable-read snapshot of the table. It includes cached
missing records, with null geometry. No Pubky references or scores are exported.

OSM object URLs on `www.openstreetmap.org`, `openstreetmap.org`, `osm.org` and
`www.osm.org` use the OSM resolver over HTTP(S), including a trailing slash or query.
Each spelling keeps its shared resource ID; matching object IDs share only the derivative
`osm_place` row. The unchanged identity crate strips fragments before classification.
Every other URL on OSM hosts (including subdomains, user pages, map views and changesets)
is refused by web, also after redirects: status `error`, link-only card, no metadata.
Malformed rows fail only their own object. Batch 429/5xx/timeout/body-cap outcomes defer
jobs without charging attempts, with Retry-After bounded to one hour. Optional editing-API
fallback is node-only.

## Compose-time previews

```sh
curl -H 'Content-Type: application/json' \
  -d '{"uri":"https://example.org/"}' \
  http://127.0.0.1:8090/v1/resolve
```

Supported URIs enter the durable queue. Ingestion and all preview callers share
one entry per normalized URI, the TTL, retry schedule and dead-letter state. A 202
response contains the resource ID for polling `GET /v1/resources/{id}`. Unsupported
schemes/namespaces or disabled resolvers return 400. Preview-only resources are not
public search results and expire after the configured orphan grace period.

Defaults allow 30 requests per minute per socket peer IP and per normalized URI.
429 responses include `Retry-After: 60`. These request budgets are separate from
fetch limits: default 1 request/second per web host, configured resolver concurrency
and rate, and 1 fetch/second per referencing author. One author can sponsor a shared
fetch; multiple tags do not multiply fetches or budget charges. Preview requests
without references use their IP budget instead. Host allow/deny lists and IP egress
checks apply to every web request, including redirects and oEmbed discovery.

## Feed visibility and errors

`/v1/info` reports `cursor`, the last observed `feed_length`, `epoch`, `lag` (their
nonnegative difference), and the timestamp of the successful poll for each feed
cursor row. A zero lag with an old timestamp does not prove Nexus is reachable.
Counts include reserved resolver kinds and preview-only resources.

Handler errors use `{"error":"..."}`; Axum's query/JSON parsing errors may be text.
Malformed query parameters return 400, malformed JSON returns 400, JSON shape
errors return 422, and request bodies over 2 MB return 413. Internal errors return
500 without database diagnostics. There are no resource write, social-state,
public admin, reverse-geocoding or place-search routes. Group curation is admin-only.

## Change feed and refresh

A page is `{lines, next_cursor, has_more, oldest_cursor}`. Each line contains
`seq`, `at` (Unix milliseconds), `resource_id`, optional `occurrence`, `source`,
`class`, `fields`, `before` and `after`. Before/after contain normalized document
facts; fetch time, TTL and body length are excluded. An OSM line also carries
attribution, and its historical document is hydrated from `osm_place.versions`.

`GET /v1/changes` accepts a nonnegative integer `cursor` (default 0), a class,
schema.org type (ancestor-aware), source and limit (1–500, default 100). Lines
are ordered by sequence ascending. Continue with `next_cursor`, keeping filters
unchanged; when caught up, it advances to the current head even if filters match
no lines. Cursor 0 starts at the oldest retained line. A nonzero cursor older
than retained history returns **410**; restart at 0 and refresh your saved resources.

`POST /v1/changes/lookup` accepts 1–500 `resource_ids` and `since` as RFC3339 text
or Unix milliseconds (integer or decimal text). The timestamp is inclusive.
Optional `cursor` and `limit` page large histories. IDs may be known or unknown;
only matching retained changes are returned. Resource history remains accessible
after orphan expiry because change records do not cascade with resource deletion.

Classes are `created`, `rescheduled` (start/end), `relocated` (location/venue),
`cancelled`, `uncancelled`, `renamed`, `details`, and `deleted`. If several fields
change together, this order chooses one class: lifecycle change, time, location,
name, details; `fields` still lists every changed field. Physical orphan expiry
emits `deleted`. A fetch failure emits no change and never cancels a resource.
The default retention is 90 days; pruning runs hourly.

Refresh rows use time to start: >30 days/no start → 7 days, 7–30 days → 2 days,
24 hours–7 days → 6 hours, <24 hours/running → 1 hour. Adapter floors may lengthen
these intervals; OSM respects its configurable cache TTL. An absent end uses the start.
One fetch at end+24 hours makes the resource final. A final resource stays frozen until
a public reference newer than its last resolution reopens it; `geo:` stays final permanently. Missing
confirmation can require one additional fetch before finalization. `lookup` and
`resolve` prioritize overdue jobs without advancing their earliest allowed retry.

## Admin metrics and canaries

`GET /metrics` is available only on the separately configured admin listener,
by default `127.0.0.1:9090`; the public route returns 404. It uses Prometheus text
format. The admin listener has no resource routes. `admin_token` (env
`PINAKES__ADMIN_TOKEN`) requires a constant-time Bearer check on all admin routes.
Non-loopback binds without a token are refused; use TLS at the reverse proxy.

Public `/v1/info` exposes manifests and status but no Nexus URL, source errors or metric
samples. Admin `GET /v1/info` includes full ingestion/source/canary state and numerical
metrics. Errors are stored only as sanitized classes; container key sets are omitted.
Info and database metric refreshes are cached for 15 seconds. Canaries default to six
hours and share worker/host budgets; due checks run at most once per worker per minute.
A web canary denied by host policy is skipped without a failure streak. OSM probes bypass
the data cache without writing it. Before the first run (or when disabled by policy), no
result gauge is exported. Generic web declares no expected fields; titleless pages and
images do not count as drift. Metric/alert details are in [ops](../ops/README.md).

Review corrections: changes use the wall clock after acquiring the sequence lock.
Prefer `cursor`; for `since`, reuse a previous response's `at` (inclusive, so deduplicate
by `seq`), not the client's wall clock. Never-observed missing resources emit no creation
or deletion. Events without an end become final at start + 24 hours. Epoch replay only
reopens final resources for references newer than their last resolution.

Public queries use a separate ten-connection pool with a five-second PostgreSQL statement
and acquisition timeout. Every public `/v1` route shares the direct-peer per-IP budget
(default 120 units/minute, configurable in `[api]`); forwarded IP headers are not trusted.
Reach-enabled searches cost `api.reach_cost` units (default 6, for up to six upstream
pages), charged before any Nexus call even when the reach cache hits. Other routes cost
one unit. Exceeding the budget returns 429 with `Retry-After: 60`.
Oldest keys are evicted when the bounded budget cache fills. Existing preview/dump limits
still apply. Dumps have per-chunk read/send deadlines (10 seconds) and a total deadline
(120 seconds), even when a reader stops polling; partial streams end in an error. The
dump's read-only transaction disables the SQL statement timeout locally, so an active
reader can drain a large snapshot beyond five seconds. Other API queries retain the limit.

`cluster` accepts finite fractional zooms, floors and clamps them to the configured table.
Large viewports coarsen to the `search.max_cluster_cells` budget (default 10000); responses
report the effective `resolution`. If the actual group count still exceeds the cap, the
request returns 400. Search ETags include the reach-author-set hash and truncation flag,
the feed cursor and a transactionally maintained write revision. Computing the revision
does not scan resources, OSM places or references.

## Event units and occurrences

`type=Event&from=...&to=...&sort=start` covers external Event pages with a start,
calendar occurrence rows and located Pubky event references. Every stage filters
these units before paging/clustering; a calendar with three matching occurrences
contributes three counts. `resource_id` is the page, owning feed or referenced venue.
Use the composite occurrence/post handle as the client row key, not `resource_id`
alone. Opaque cursor keys distinguish instances even when their ranks and owner IDs tie.

A feed result adds `occurrence: {uid, recurrence_id, event_resource_id?}`. A null
recurrence_id represents a non-recurring instance; recurring keys are UTC instants
or all-day dates. An existing page matching the occurrence URL is linked by
`event_resource_id`, only for a different resource on the same host or a configured
`event.container.link_hosts` host. URL-less instances have a null URL/link; references
never trigger an unsolicited fetch.
A located Pubky result adds `event: {author, object_path, recurrence_id, start, end,
status}` for Nexus post hydration. Its name is intentionally absent: Pinakes does
not fetch the post body. Author/reach filters also constrain that post's author.
`venue=<id>` matches promoted venue IDs and the referenced venue for Pubky units.
Cancelled units retain their lifecycle status and remain addressable.

`GET /v1/resources/{id}/occurrences?from=...&to=...` returns accepted occurrences
ordered by start, UID and recurrence key. `limit` defaults to 100 and cannot exceed
500. Use the returned signed `cursor` for the next page; it fixes the resource and
time window, and expires on daemon restart. A tampered or mismatched cursor is 400.
Items include the full bounded `document`, their identity handle, start/end, name,
status, URL, venue/page link, volatile flag and optional supersedes key. This route
accepts RFC 3339 dates; search additionally accepts Unix milliseconds. A known
non-calendar returns an empty array. `from` defaults to the last accepted horizon
start (otherwise the configured horizon); an explicit earlier bound can read
retained older rows. Superseded rows are excluded.

Event documents add `tz?`, `all_day?`, `event_status`, `attendance`,
`venue: {text,name?,address?,resource_id?,location?,location_source?,osm_id?,osm_version?}`,
`organizer: {name,url?}`, and optional display-only `offers: {low_price,high_price,currency}`.
Lifecycle is `scheduled|cancelled|postponed|rescheduled|moved_online`; attendance is
`offline|online|mixed`. Top-level `status` still means fetch health. Calendar
CATEGORIES become a bounded deduplicated `categories` array, independent of Pubky tags.

An offset-only timestamp keeps its instant without inventing a zone. Floating
calendar times use TZID/X-WR-TIMEZONE/configured default/coordinates where available.
Without a zone, `start_local` and `end_local` preserve wall times; UTC values are a
sorting proxy, not a known instant. Unknown TZIDs use an advertised/default zone
or a flagged UTC fallback. All-day ends are exclusive and stay local dates across DST.
`timezone_attribution` accompanies coordinate-derived zones; preserve it in display
along with any OSM `attribution`. See the separately licensed data in `data/README.md`.

Calendar validators commit with the parsed snapshot and its `horizon_end`. They are
sent only after a saved snapshot, with no pending missing/held keys or missing parent,
and with more than half the configured forward window remaining. Otherwise an
unconditional GET obtains a body for confirmation or recurrence expansion. Eligible
304s renew TTL; they neither confirm disappearance nor advance the expansion horizon.
A prior feed returning HTML 200 or HTTP 404/410 counts as an empty observation. Two
observations cancel mutable rows and mark the parent missing, hiding its units from
search; retained history remains available at the occurrence route. A valid body can
restore the feed. The first observation counts toward `feed_held_total`/`FeedHeld`.
Mixed dated/undated RSS/Atom/JSON feeds keep usable dated items and warn; unparseable
starts add `invalid_feed_item_date` without failing healthy siblings.

Calendar rows use SEQUENCE/LAST-MODIFIED and normalized content hashes; DTSTAMP,
unknown vendor props and fetch noise do not create changes. Explicit cancellations
apply immediately. Disappearance needs two fresh complete snapshots. Losing over half
the active keys holds all updates until the next identical successful snapshot.
Occurrence changes are field patches with `occurrence` equal to the serialized
`[uid,recurrence_id]` key. Above `event.container.max_changes` (100 default), a
single feed-level `details` change has `after.occurrence_changes` with the count;
clients refresh the occurrence window. New UID keys with identical content
supersede the old row without cancellation, with `supersedes` on the created
change. Snapshots older than or equal to the last observation are ignored; past
end+24h and horizon roll-off never imply cancellation. Retained cancelled,
superseded or past-horizon rows are purged after end + configured retention.
Total rows/new-key rotation are capped; repeated holds back off from the normal
cadence and eventually dead-letter, instead of polling every minute.

Nexus `kind:event` puts/deletes accept `recurrence_id`, start/end Unix milliseconds
and optional status. The reference key includes author, object_path, venue resource
and recurrence so deleting one occurrence leaves other instances/venues intact.
Bad recurrence keys (over 128 bytes or NUL), out-of-range timestamps and end before
start are skipped and
counted as `pinakes_ingest_rejected_total{reason="event"}` after commit. An invalid
feed `at` timestamp uses reason `timestamp`, for every reference kind. Unknown
lifecycle strings are treated as absent and keep the otherwise valid reference.

Identity mismatches and URI normalization failures are skipped with finite ingestion
reasons `identity` and `uri`; valid siblings and the feed cursor still commit.

### Platform manifests and cursor sources

`/v1/info.manifests` includes the registered platform adapters. Each entry has
`source`, `mode`, `cadence_floor`, `identity`, `cancellation`, `expected_fields`,
`canary`, `canary_note`, `ua_profile`, `requires_key`, `enabled`, `disabled_reason`
and `fragile`. A missing API key disables only its adapter; no key is returned.
Canary status is per adapter, with fixed metric labels. Cursor values are internal
per-resource state and are not exposed by this endpoint. Public source state reports
aggregate resets and health; a cursor reset never changes resource identities.

Portal, BTC Map, Google Calendar API and Nostr calendars produce the same occurrence
and search units as ICS feeds. Explicit delta tombstones apply immediately; omission
from a delta does not cancel a row. Expired cursors trigger full resync under the
ordinary held-snapshot rules. BTC Map websites and Nostr calendar members are queued
as independent resources. Portal OSM venue data uses the existing ODbL projection and
licence boundary. All existing resource and occurrence routes and cursors are unchanged.


## Groups and identifier cards

Resources and lookup responses include `group` when membership has been computed.
A group card has `id`, `kind`, `name`, `image`, `attribution`, `curated`, `taggers`, `references`
and `members: [{resource_id, uri, site, occurrence?}]`. The optional occurrence
contains `uid` and `recurrence_id`. Group IDs are views and can change when evidence
joins or splits a group; member resource IDs and references never change. Ranking
scores remain internal. Resource reads keep their own name/image in the attached
group summary; group lookup and collapsed search use the best member. OSM best
members carry attribution.

`collapse=group` applies all filters to individual members first, then returns the
group's preselected best member with its group card. Thus a group can match a tag,
host or location on another member. Best-member facets and internal group scores
are precomputed; taggers count distinct authors over all member references. Tag
facets count groups once per label. Clusters count groups; their `top` entries are
best-member resource IDs for the existing hydration contract. Fetch the group card
to hydrate every member through Nexus `by_ids`. Unprocessed upgrade rows remain
individual results until the bounded grouping pass reaches them.

Automatic grouping uses typed identifiers, podcast GUIDs, ICS UID, `sameAs`,
canonical URLs and accepted OSM URL identity. URL claims require the same
registrable domain or reciprocity. Cross-domain typed keys require verified evidence
on both members or reciprocal links. Only ICS UID keys are scoped to exact start;
occurrence joins also reject starts more than five minutes apart. Any pair of points
over `queue.groups.max_distance_m` (default 500 m) prevents an automatic merge.
FIFO and per-origin admission caps reject new excess joiners without dropping
established groups. Singletons stay individual; grouping failures back off separately
and cannot prevent a resource save.

On the **admin listener only**:

```http
PUT /v1/groups/aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
Authorization: Bearer <admin-token>
Content-Type: application/json

{"name":"A curated recording","image":null,"members":[{"resource_id":"0123456789abcdef0123456789abcdef","occurrence":null}]}
```

This replaces the explicit member set and optional name/image. An occurrence member
uses `{"uid":"calendar-uid","recurrence_id":"2026-10-20T17:00:00Z"}`. Members must
already exist and have been reconciled. Curation exclusively pins these members
away from automatic groups and can override automatic distance/evidence rules;
removing a member allows its automatic evidence to be reconsidered. Every admin
route requires a Bearer token when `admin_token`/`PINAKES__ADMIN_TOKEN` is configured,
and a non-loopback admin bind requires it. Database failures return 500; invalid
curation returns 400. `queue.groups.enabled=false` disables grouping reads, writes and collapse;
stored membership remains available if the module is re-enabled.

Five independent manifests (`media`, `isbn`, `doi`, `nostr`, `activitypub`) appear in
`/v1/info`, alongside card-worker status and the effective grouping limits; configure them under `[cards.<kind>]`. `isbn:` checks ISBN-10/13 checksums
and calls Open Library. Valid `doi:`, `https://doi.org/…` and `https://dx.doi.org/…`
request CSL JSON, including publication date and container. Invalid bare identifiers
are final Missing; informational DOI URLs fall back to web. Generic Nostr
profiles/notes use the signed-event indexer path; NIP-52 events retain their event
schema. Advertised ActivityPub endpoints or ActivityStreams JSON yield Person,
Article or SocialMediaPosting cards only when the fetched URL and object ID share
the page’s registrable domain. Social note excerpts are capped at 200 characters,
refresh at most hourly and lose history on disappearance. Unlisted AP content is
omitted. Unknown signed Nostr kinds yield a generic card. Media queries oEmbed
first; healthy page JSON-LD takes precedence. A successful oEmbed answer survives
a failed or truncated page; oversized HTML yields head metadata with `truncated`
and drift. Feed caps remain strict. Podcast types require a namespace or a selected
audio/video enclosure; plain RSS is a DataFeed. Direct podcast feeds, including
single-item feeds, are PodcastSeries; `?guid=` or the episode page’s matching RSS
link selects an episode. No embed HTML or media bytes are served. Disabled non-HTTP identifier routes defer; enabled web can
still render ordinary HTTP fallback cards.
