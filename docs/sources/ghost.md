# Ghost

Posts on any site running Ghost. This source is a page hook: it never claims links by their
shape. The web route fetches the page as usual, and when the page is generated by Ghost and
carries its site's public Content API key, the card takes the post's title, excerpt, feature
image, dates, authors and tags from the Content API. Ghost documents these keys as safe to
expose; requests that carry one are still kept out of stored addresses and logs.

## Pages

A page qualifies when its head has `<meta name="generator" content="Ghost …">` and a script with
`data-key` (the public key) and `data-api` (the Content API, `…/ghost/api/content/`), as Ghost's
portal and search scripts do. The API must be on the page's own origin; a site whose API is on
another host (e.g. `*.ghost.io` behind a custom domain) keeps its own card. The post is found by
the page's last path segment (its slug), and must name the page's own address.

## What it reads

`GET {api}posts/slug/{slug}/?key={key}&include=authors,tags&fields=id,uuid,title,url,custom_excerpt,excerpt,feature_image,published_at,updated_at`
(a few KB), within the web fetch's deadline and at most 3 seconds. A failed or refused request
leaves the page's own card.

## Card

The page's card with the post's title, excerpt (the custom excerpt, else Ghost's; at most 300
characters) and feature image. A page typed as an article keeps its type; any other becomes
`BlogPosting`. `details.from` is `ghost`.

| Fact | Meaning |
| --- | --- |
| `published`, `modified` | When the post was published and last changed |
| `author` | Its authors |
| `tags` | Its public tags (internal `#` tags are left out) |
| `uuid` | The post's id on its site, which survives a change of its address |
