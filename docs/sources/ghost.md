# Ghost

Pinakes improves the cards of posts on any site running Ghost, from the site's own Content API.
This source is a page hook: it never claims links by their shape. The web route fetches the page
as usual. When the page is generated by Ghost and carries its site's public Content API key, the
card takes the post's title, excerpt, feature image, dates, authors and tags from the Content API.
No key of your own is needed.

| | |
| --- | --- |
| Source | `ghost`, official source, page hook |
| Links | None claimed: web pages whose head marks them as Ghost pages (see [Pages](#pages)) |
| Fetches | `GET {api}posts/slug/{slug}/?key={key}&include=authors,tags&fields=…` on the page's own origin |
| Credentials | None (the site's public Content API key, read from its page) |
| Rate | Shared per-host default (`limits.host_requests_per_second`), per site |
| Refresh | With the page ([refresh](../design.md#refresh)) |
| Card types | The page's article type (`Article` or a subtype), else `BlogPosting` |
| Keys | None (facts only) |
| Credit | None |
| Switch | `[sources.ghost] enabled`, on by default |

## Pages

The hook runs on a page the web route fetched with a 200 answer, an HTML content type and an
ordinary card. It does not run on a card that ActivityPub or a podcast feed made.

A page qualifies when its head holds both:

- `<meta name="generator" content="Ghost …">`;
- a script with `data-key` (the public key) and `data-api` (the Content API), as Ghost's portal
  and search scripts have.

The Content API must be on the page's own origin, and its path must end in
`/ghost/api/content/`, without a query. A site whose API is on another host, such as `*.ghost.io`
behind a custom domain, keeps its page's own card. The key must be 20 to 64 hexadecimal
characters.

The post is found by the page's last path segment, its slug: lower-case letters, digits and
hyphens, at most 191 characters. The post the API returns must name the page's own address as its
`url`, and must have a title. Otherwise the page keeps its own card.

## What it fetches

One request per page, on the page's own origin:

```text
GET {api}posts/slug/{slug}/?key={key}&include=authors,tags&fields=id,uuid,title,url,custom_excerpt,excerpt,feature_image,published_at,updated_at
```

The request runs within the web fetch's deadline and takes at most 3 seconds. Ghost documents
these keys as safe to expose; requests that carry one are still kept out of stored addresses and
logs. Any answer other than 200, an error or a timeout leaves the page's own card.

## Card

The card is the page's own card with these changes:

- `name` is the post's title.
- `description` is the post's custom excerpt, else Ghost's excerpt, at most 300 characters.
- `image` is the post's feature image, when it has one.
- A page typed as an article (`Article` or a subtype) keeps its type; any other becomes
  `BlogPosting`.
- `from` is `ghost`.

| Fact | Meaning |
| --- | --- |
| `published` | When the post was published, as Ghost gives it |
| `modified` | When the post was last changed, as Ghost gives it |
| `author` | The post's authors, by name |
| `tags` | The post's public tags; internal tags (`#name`) are left out |
| `uuid` | The post's ID on its site, which survives a change of its address |

## Keys and groups

A page hook's card joins nothing: the `uuid` is a fact only.

## Credit

The card credits nothing.

## Turn it off

```toml
[sources.ghost]
enabled = false
```

Ghost pages then keep the card the web route makes from their own metadata.
